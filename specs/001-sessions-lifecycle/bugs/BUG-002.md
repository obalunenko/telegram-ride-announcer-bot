# Bug Report: Storage Failures in the Session Middleware Are Silent

**Type**: Spec gap
**Severity**: Medium
**Feature**: 001-sessions-lifecycle
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

When `setSessionMiddleware` fails to load or create the user or the session,
it logs the error and drops the update. The user gets no reply and cannot
tell whether the bot is working.

Decision: reply with a short error message to the chat of the update and
still drop it.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 4 — Robust Update Handling
- **Affected requirements**: FR-006 ("log the error and drop the update")
- **Gap identified**: Gap 2; the edge case "Storage failure while loading or
  creating the user or session"

### plan.md
- **Affected sections**: Design Decisions (middleware)
- **Impact**: a shared error reply that does not need a session

### tasks.md
- **Affected tasks**: T008, T017, T021
- **False completions**: none
- **Missing tasks**: error reply helper, use it in the middleware, test the
  reply for every failure case

## Root Cause Analysis

The middleware was written to keep the chain safe, not to inform the user;
the spec recorded the silent drop as behavior.

## Recommended Fix

1. Add `msgSomethingWentWrong` and `replyError(ctx, chatID)` in
   `internal/service/helper.go`.
2. Call it in every failure branch of `setSessionMiddleware`.
3. Assert the reply in the failure cases of `TestSetSessionMiddleware` and
   assert no reply for ignored updates.
