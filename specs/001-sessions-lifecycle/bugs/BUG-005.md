# Bug Report: Panics Give No Reply and Print the Stack to Stdout

**Type**: Spec gap
**Severity**: Low
**Feature**: 001-sessions-lifecycle
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

`panicRecovery` recovers a handler panic and logs it, but the user who sent
the message gets no reply, and the stack trace is printed with
`fmt.Println` to stdout, outside the structured logger.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 4 — Robust Update Handling
- **Affected requirements**: FR-007 (recover, log, keep handling)
- **Gap identified**: Gap 5

### plan.md
- **Affected sections**: Design Decision "Middleware order"
- **Impact**: the recovery uses the error reply from BUG-002

### tasks.md
- **Affected tasks**: T018, T021
- **False completions**: none
- **Missing tasks**: reply and log the stack as a field; tests

## Root Cause Analysis

The recovery was written for debugging and never revisited for users or log
collection.

## Recommended Fix

1. Log the panic value and the stack as fields of one error entry.
2. Reply with the error message when the update has a message.
3. Test the reply and the case without a message.
