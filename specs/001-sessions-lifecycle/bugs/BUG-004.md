# Bug Report: Shutdown Skips Stopping Polling When Sessions Cannot Be Listed

**Type**: Implementation drift
**Severity**: Medium
**Feature**: 001-sessions-lifecycle
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

`Service.Shutdown` lists the sessions to send farewells. When listing fails,
it logs the error and returns, so the stop functions never run: long polling
is not canceled and in-flight updates are not awaited.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 3 — Graceful Shutdown With a Farewell
- **Affected requirements**: FR-011 (stop long polling and wait for updates)
- **Gap identified**: Gap 4; the edge case "Session list fails during
  shutdown"

### plan.md
- **Affected sections**: Design Decision "Shutdown order"
- **Impact**: farewells and stopping are independent steps

### tasks.md
- **Affected tasks**: T014 (marked complete, but FR-011 is not met when
  listing fails)
- **False completions**: T014
- **Missing tasks**: always run the stop functions; test the failure

## Root Cause Analysis

The early `return` on the listing error was meant to skip the farewells but
also skipped the rest of `Shutdown`.

## Recommended Fix

1. Move the farewells into `sayGoodbye`; `Shutdown` calls it and then always
   runs the stop functions.
2. Test that the stop functions run when listing sessions fails.
