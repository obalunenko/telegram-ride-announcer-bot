# Bug Report: User Profile Is Never Refreshed

**Type**: Spec gap
**Severity**: Low
**Feature**: 001-sessions-lifecycle
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

The bot stores the user's username, first name, and last name on first
contact and never updates them. After a user changes their Telegram profile,
trip cards and greetings keep showing the old values.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Returning User Keeps Their Dialog
- **Affected requirements**: FR-001; Key Entities (User: "Created once, never
  updated")
- **Gap identified**: Gap 3; the edge case "Changed Telegram profile"

### plan.md
- **Affected sections**: Project Structure (`ops/users.go`)
- **Impact**: an update operation in the users repository and in `ops`

### tasks.md
- **Affected tasks**: T002, T006, T008
- **False completions**: none
- **Missing tasks**: repository `Update`, `ops.UpdateUser`, refresh in the
  middleware, tests

## Root Cause Analysis

The users repository had no update operation, so the middleware could only
create users.

## Recommended Fix

1. Add `Update` to the users repository and `ops.UpdateUser`.
2. In the middleware, compare the stored profile with the message sender and
   update it when it differs; a failed update gets the error reply.
3. Test the refresh and the failure.
