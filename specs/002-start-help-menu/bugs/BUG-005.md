# Bug Report: No Service-Level Test for the `/help` Command List

**Type**: Untested flow
**Severity**: Low
**Feature**: 002-start-help-menu
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

The service tests check only the header of the `/help` reply. Nothing checks
that it lists exactly the enabled commands, in order, and hides disabled
ones, so BUG-004 went unnoticed.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 2 — Command List on `/help`
- **Affected requirements**: FR-002, FR-006
- **Gap identified**: Gap 5

### plan.md

- **Impact**: a service test with declared commands

### tasks.md
- **Affected tasks**: T010
- **False completions**: none
- **Missing tasks**: the service test and a constructor that takes bot
  options

## Root Cause Analysis

The test service was built without declared commands, so `/help` listed
nothing in every test.

## Recommended Fix

1. Add `newTestServiceWithAPI` that takes bot options and the number of
   startup calls.
2. Test `/help` with enabled and disabled commands while the menu update
   fails.
