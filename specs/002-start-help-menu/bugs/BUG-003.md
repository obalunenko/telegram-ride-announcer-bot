# Bug Report: `/start` and `/help` Stay Silent When They Fail

**Type**: Spec gap
**Severity**: Low
**Feature**: 002-start-help-menu
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

When `/start` or `/help` fails to save the session, to discard the draft
trip, or to render its template, it logs the error and sends nothing.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 and User Story 2
- **Affected requirements**: FR-011 ("log the error and send no reply")
- **Gap identified**: Gap 3; the edge case "Saving the session or rendering
  a template fails"

### plan.md
- **Affected sections**: Design Decisions
- **Impact**: the handlers use `replyError` from 001 BUG-002

### tasks.md
- **Affected tasks**: T006, T009, T010
- **False completions**: none
- **Missing tasks**: reply on failure; assert it in `TestHandlers_Failure`

## Root Cause Analysis

The spec recorded the silent failure; there was no shared error reply until
001 BUG-002.

## Recommended Fix

1. Call `replyError` after logging every failure in `startHandler` and
   `helpHandler`.
2. Assert the reply in `TestHandlers_Failure`, including a failing draft
   discard.
