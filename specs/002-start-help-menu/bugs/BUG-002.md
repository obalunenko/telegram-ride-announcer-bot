# Bug Report: `/start` and `/help` Silently Abandon a Trip Dialog

**Type**: Spec gap
**Severity**: Medium
**Feature**: 002-start-help-menu
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

`/start` and `/help` reset the dialog state to `StateStart` but keep the
draft trip in the session and in storage, and say nothing about it. The
abandoned draft later shows up in `/mytrips`.

Decision: a command that ends a trip dialog deletes the draft and tells the
user "Your unfinished trip is discarded." (the same applies to `/newtrip`
and the new `/cancel` in 003).

## Root Cause Analysis

The handlers reset only the state field; nobody owned the draft trip.

## Recommended Fix

1. Add `discardDraft` (delete the draft trip) and `resetDialog` (discard,
   notify, save in `StateStart`) in `internal/service/handlers.go`.
2. Use `resetDialog` in `startHandler` and `helpHandler`.
3. Test both commands in the middle of `/newtrip`.
