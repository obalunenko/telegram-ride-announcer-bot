# Bug Report: Published Trips Are Never Marked Completed

**Type**: Implementation drift
**Severity**: High
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

`publishTrip` calls `ops.UpdateTrip` with `Completed: true`, but
`ops.UpdateTrip` does not pass `Completed` to the trips repository, and
`models.Trip` has no completed field. Published trips stay drafts in
storage, so drafts and published trips cannot be told apart (and `/mytrips`
lists both, 004).

- **False completions**: T003 (drops `Completed`), T014 (publishing does not

- **Missing tasks**: pass the flag, add it to `models.Trip`, tests for the
  trips repository and `ops/trips.go`

## Root Cause Analysis

`ops.UpdateTrip` copies the params field by field and missed `Completed`.
`internal/ops/trips.go` and the trips repository had no tests of their own,
and the service tests never checked the flag.

## Recommended Fix

1. Pass `Completed` in `ops.UpdateTrip`; add `Completed` to `models.Trip` and
   map it in `GetTrip` and `ListTripsByUser`.
2. Tests for the trips repository and `ops/trips.go`; check the flag after
   publishing in `TestService_PublishTrip`.
3. Drop the trip packages from the constitution Known Deviations.
