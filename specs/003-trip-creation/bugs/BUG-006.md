# Bug Report: Free Text After Cancel Starts a New Trip

**Type**: Implementation drift
**Severity**: Low
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

Answering `no` at the confirmation leaves the state `StateNewTrip`. The next
free-text message is routed to the trip dialog and silently creates a new
draft trip, instead of getting the "Command not found" reply.

Decision: canceling ends the dialog in `StateStart`; a new trip starts only
with `/newtrip`.

## Root Cause Analysis

`cancelTrip` set `StateNewTrip` to let the user start again, but that state
also routes free text to the dialog.

## Recommended Fix

1. `cancelTrip` saves `StateStart`.
2. Check the state and a free-text reply after cancel in
   `TestService_CancelTrip` and `TestService_ConfirmTrip`.
