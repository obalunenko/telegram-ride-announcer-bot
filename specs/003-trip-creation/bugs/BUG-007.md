# Bug Report: Announcement Goes to the Session's First Chat

**Type**: Dependency issue
**Severity**: High
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

Prompts, the announcement, and the pin go to the session's chat. Because the
session kept the chat of the user's first message (001 Gap 1), a user who
first talked to the bot privately had every trip announced and pinned in the
private chat, even when they ran `/newtrip` in a group.

- **Gap identified**: Gap 7; the edge case "Dialog in a private chat"

- **Missing tasks**: a test that the dialog chat gets the announcement and
  the pin

## Root Cause Analysis

The behavior followed from the one-session-per-user design in 001, which
specs/001-sessions-lifecycle BUG-001 replaced with one session per user and
chat.

## Recommended Fix

1. No code change here: since 001 BUG-001 the session's chat is the chat of
   the dialog.
2. Test a user who writes privately first and then creates the trip in a
   group: the prompts, the announcement, and the pin go to the group, and
   both chats get the farewell.
