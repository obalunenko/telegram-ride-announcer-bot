# Bug Report: `/newtrip` During the Dialog Becomes the Answer, and There Is No Way to Cancel

**Type**: Spec gap
**Severity**: Medium
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

When a user sends `/newtrip` in the middle of the trip dialog, the handler
sees a trip state and passes the text to the current step, so the trip is
named `/newtrip` (or gets that date or description). The only way out of the
dialog is to answer `no` at the very end.

Decision: `/newtrip` always starts over; when a dialog is unfinished, it
deletes the draft and replies "Your unfinished trip is discarded." first. A
new `/cancel` command ends the dialog on any step with the same reply, or
answers "There is nothing to cancel." outside of a dialog. The first prompt
mentions `/cancel`.

## Root Cause Analysis

`textHandler` reused `newTripHandler` for dialog answers, so the command
handler had to keep the state when the user was in a trip state.

## Recommended Fix

1. `newTripHandler` calls `resetDialog(ctx, sess, StateNewTrip)` (from 002
   BUG-002, now taking the target state) and starts the dialog.
2. `textHandler` routes trip states to a new `tripAnswerHandler`.
3. Add `CmdCancel`, `cancelHandler`, the menu entry, and the README line.
4. Test restarting and canceling on several steps and outside a dialog.
