# Bug Report: Failed Trip Steps Give No Reply

**Type**: Spec gap
**Severity**: Medium
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

When a step of the trip dialog fails (storage, rendering, or a Bot API
call), the error is logged and the user gets nothing. A failed pin is
reported as a failed step although the announcement is already sent, the
trip is published, and the state is saved.

Decision: a failed step, `/newtrip`, or `/cancel` replies with the shared
error message; the failed step keeps the state, so the user can answer
again. A failed pin does not fail publishing: the bot replies "The trip is
published, but I couldn't pin it. To pin announcements, make me an admin
who can pin messages."

## Root Cause Analysis

The step functions return errors that the handlers only logged; the pin
error was returned like any other.

## Recommended Fix

1. `runTripStep` in `internal/service/trips.go` runs `createTrip` and
   replies with `replyError` on failure; `newTripHandler` and
   `tripAnswerHandler` use it; `newTripHandler` and `cancelHandler` reply
   when the reset fails.
2. `publishTrip` logs a failed pin and sends `msgPinFailed` instead of
   returning an error.
3. Tests: failure replies in `TestHandlers_Failure`, `TestService_PinFails`.
