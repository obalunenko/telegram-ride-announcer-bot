# Bug Report: Trip Date Is Free Text Without a Time

**Type**: Spec gap
**Severity**: High
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

The date step stores any text as the trip date. `today` is stored literally,
so its meaning depends on when the card is read; nothing is validated; and
although the prompt asks for "date and time", no time is asked.
`StateNewTripTime` exists but no step uses it. Trips cannot be sorted or
filtered by date (004).

Decision: the date step accepts `today`, `tomorrow`, or `DD.MM.YYYY` and
rejects past dates; a new time step (`StateNewTripTime`) accepts `HH:MM` and
rejects a start that has passed. The trip stores the start as a time value
in the bot's time zone, `RIDE_ANNOUNCER_TIMEZONE` (IANA name, default
`UTC`). Invalid or past input is asked again.

## Root Cause Analysis

The first version stored the keyboard answer as text and left the time step
for later.

## Recommended Fix

1. `time.Time` dates in `models.Trip`, the trips repository, and `ops`.
2. `parseTripDate`, `parseTripTime`, `formatTripDate` in
   `internal/service/dates.go`; `setTripDate` asks for the time; new
   `setTripTime`.
3. `service.WithLocation` and an injectable clock; read
   `RIDE_ANNOUNCER_TIMEZONE` in `main` and embed `time/tzdata`.
4. README and Docker Compose; tests for parsing, the dialog, and a non-UTC
   zone.
