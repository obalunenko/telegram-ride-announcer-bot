# Bug Report: Abandoned Draft Trips Stay in Storage

**Type**: Spec gap
**Severity**: Medium
**Feature**: 003-trip-creation
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

A draft trip is created on the first step of `/newtrip`. When the dialog is
interrupted by `/start`, `/help`, or a second `/newtrip`, the draft is left
in storage and later appears in `/mytrips`.

## Artifact Traceability

### spec.md
- **Affected user story**: User Story 1 and User Story 3
- **Affected requirements**: FR-001, FR-011
- **Gap identified**: Gap 8; the edge case "Interrupted dialog"

### plan.md
- **Affected sections**: Design Decision "Draft trip from the first step"
- **Impact**: every command that ends the dialog deletes its draft

### tasks.md
- **Affected tasks**: T007
- **False completions**: none
- **Missing tasks**: none beyond the fixes below

## Root Cause Analysis

Nothing owned the draft when a command other than `no` ended the dialog.

## Recommended Fix

Already covered by other fixes; no code change here:

1. `/start` and `/help` delete the draft (002 BUG-002).
2. `/newtrip` deletes the draft before it starts over, and `/cancel`
   deletes it on any step (BUG-003).
3. A failed step keeps the dialog, so its draft is not abandoned (BUG-005).
4. A restart loses all data anyway (in-memory storage).

Tests: `TestService_InterruptTrip` (002), `TestService_NewTripRestarts` and
`TestService_CancelCommand` (BUG-003).
