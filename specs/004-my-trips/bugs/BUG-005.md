# Bug Report: `/mytrips` Lists Past Trips Forever

**Type**: Spec gap
**Severity**: Low
**Feature**: 004-my-trips
**Reported**: 2026-11-15
**Status**: Patched
**Patched**: 2026-11-15

## Description

Every published trip stays in `/mytrips` after it has taken place. With
free-text dates nothing else was possible; since 003 BUG-004 every trip has
a real start.

Decision: `/mytrips` lists only upcoming trips, those that start after now;
past trips are hidden. The header, the empty reply, the menu description,
the welcome, and the README say "upcoming".

## Root Cause Analysis

Dates were free text when the list was built.

## Recommended Fix

1. Replace `publishedTrips` with `upcomingTrips(list, now)` in
   `internal/service/mytrips.go`; the handler passes `s.now()`.
2. `msgNoUpcomingTrips` and `myTripsHeader`; menu description "show your
   upcoming trips"; welcome and README.
3. Tests: `TestUpcomingTrips`, `TestMyTripsHandler_UpcomingOnly`; test trips
   start tomorrow.
